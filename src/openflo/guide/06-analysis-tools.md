# Analysis tools

## Clustering and embeddings

**Analyze > Cluster…** runs PhenoGraph, Leiden or FlowSOM on chosen channels, optionally with a UMAP. Set the UMAP's **Components** to 3 for a 3D embedding (UMAP1, UMAP2, UMAP3): the 3D plot then opens on it, colored by cluster; the 2D plot shows any two of the three. A later 2-component run removes UMAP3, and an open 3D plot that showed it picks its axes again; a gate drawn on UMAP3 stays in the tree, with no events and its statistics NA, until a 3-component run writes UMAP3 again. `openflo-run --umap-components 3` does the same for each group's UMAP and also writes `<group>_umap3d.gif` (one turn, colored by cluster) and `<group>_umap3d.csv` (UMAP1-UMAP3, cluster and sample for each embedded event); a 2-component run into the same folder removes those two files. Clusters appear as populations you can switch on in the tree. **Events / sample** set to Default clusters at most 200,000 events of each sample with PhenoGraph or Leiden (50,000 with FlowSOM) and gives every other event the cluster of its nearest clustered event; All events clusters every event, and the dialog first asks, with the memory it needs, before a PhenoGraph or Leiden run that big or one larger than free memory. **Cancel clustering**, beside the busy bar, stops a run after the step it is on. Leiden's **Fast graph** is on by default: it links each cell only to its own nearest neighbors, as PhenoGraph does, and needs about a ninth of the memory of the older graph (about 2.4 GB against 21 GB at 200,000 events); turn it off only to compare with runs made the older way, since the clusters differ. FlowSOM starts at 20 metaclusters here, in `openflo-run --n-metaclusters` and in `FlowSample.run_flowsom`: keep it above the number of populations you expect, because asked for exactly that many it tends to merge a rare population into a neighbor; join two metaclusters that are one population with an OR gate. **Analyze > Compare embeddings…** runs several embedding methods side by side, and **Analyze > SOM tree…** draws the FlowSOM tree. **Analyze > Annotate…** labels clusters or populations.

PhenoGraph and Leiden have a **Resolution** (default 1.0, the standard result). It sets how finely cells are split: higher gives more, smaller clusters, lower merges them. PhenoGraph tends to split one population into several clusters when there are only a few markers; if that happens, lower the resolution to about 0.3–0.5 and run again. For PhenoGraph the resolution needs **Reproducible** ticked (the default): its non-reproducible Louvain method has no resolution, so the box is grayed out without it. The value used is kept in the session's history and in the Methods text. From the command line, `openflo-run --resolution 0.5` does the same for either method.

## 3D plot

**Analyze > 3D plot…** draws three channels of one sample, or the three components of a 3D embedding (UMAP1/UMAP2/UMAP3), as a cloud you turn. Drag to rotate and scroll to zoom (on a touchpad, small scrolls zoom a little); **Reset view** goes back to the angled start and **Front (X/Y)** looks straight down Z, which is the 2D plot of X against Y. Each axis uses the same scale as the 2D plot (log, logicle, symlog, linear, and any axis range you set; a range starting at 0 on a log axis starts where the 2D plot's does). **Population** draws what the main plot shows, every event, or one gate. **Color by** density in 3D, a channel's value, a cluster column, or one gate (inside in its color, the rest gray). At most 200,000 events are drawn: a random subset picked with the **Seed**, so the same seed always shows the same events, and the line under the plot says how many are shown. **Save PNG…** saves the view; **Save GIF…** saves one full turn (36 or 72 frames, about six seconds, looping), and **Save MP4…** does the same as a video when ffmpeg is installed. Both are saved at the window's size, up to 1,280 pixels on the long side, and an existing file is only replaced once the new one is complete.

On the phone, **3D view** under the plot shows the same cloud: pick X, Y and Z, turn it with one finger and pinch to zoom; **Reset** and **Front (X/Y)** work as on the desktop. Each axis uses the 2D plot's scale over the sample's whole range (a zoom on the 2D plot is not carried over). Dots are colored by 3D density, with the same smoothing and color spread as the desktop. The phone draws at most a twentieth of its event cap (100,000 events on Android, 50,000 on iPhone), as a random subset with seed 42, and says so under the view. **Save GIF** saves one full turn (36 frames, about six seconds, looping) at 480 pixels.

## Cell cycle

**Analyze > Cell cycle…** models DNA content. The Dean-Jett-Fox model (Fox, 1980) fits the G1 and G2/M peaks and an S phase between them, and reports their areas, so S-phase cells under the peaks count as S. The Boundaries model counts events between intensity cut-offs instead. A width channel, when present, removes doublets first. The phases become populations.

## Proliferation

**Analyze > Proliferation…** fits a dye-dilution histogram as generations one halving apart. Pick the dye channel and the population (live singlets, say), and either let OpenFlo find the undivided peak or take it from an unstimulated control. The window reports the cells in each generation and the standard indices (Roederer, 2011): percent divided, division index, proliferation index and expansion index. With fewer than 50 cells the indices read NA.

## Kinetics

**Analyze > Kinetics…** plots a channel over acquisition time for each sample, as for calcium flux: the median (or mean) in each time bin, overlaid. Each sample's baseline, peak, time to peak, area over baseline and peak over baseline are listed and export as CSV. Time is in seconds when the file gives the tick length, otherwise in ticks.

## Trajectories

**Analyze > Trajectory…** orders cells by pseudotime along a path through marker space, for differentiation series.
